# 竞赛平台三端优化与新增需求文档

> 基于当前项目代码扫描结果整理，面向教师端、学生端、管理员端给出可执行的优化与新增需求。

## 1. 文档目标

本文件用于指导当前竞赛平台下一阶段产品优化与功能完善，重点覆盖：

1. 教师端哪些功能已经具备主链路、但体验和数据能力仍需增强。
2. 学生端哪些功能已上线但存在半成品、静态演示或缺少闭环的问题。
3. 管理员端哪些模块可以继续做深，哪些页面需要从“展示壳”升级为“业务页”。

本文档尽量做到可执行，因此每项需求都包含：

- 问题描述
- 目标与价值
- 优先级
- 涉及模块
- 验收标准
- 实施建议

---

## 2. 项目扫描结论

### 2.1 技术与结构判断

- 后端为 Spring Boot 多模块工程，核心业务在 `compserve-admin`、`compserve-system`、`compserve-framework`。
- 前端为 Vue 3 + Element Plus，业务页面集中在 `compserve-ui/src/views`。
- 当前系统已经形成三类角色主入口：
  - 学生端：`src/views/student`
  - 教师端：`src/views/teacher`
  - 管理员端：`src/views/admin` 与 `src/views/sys-admin`

### 2.2 当前成熟度判断

#### 已具备真实业务主链路的模块

- 学生端竞赛列表、竞赛详情、报名、组队邀请/申请、材料提交。
- 学生端模拟考试、刷题训练、训练记录。
- 教师端赛事查看、评审列表、队伍详情、评分提交/修改/删除。
- 管理员端竞赛管理、题库管理、试卷管理、教师赋权、评分结果、赛事详情。
- 教师/学生基础账号管理、教师批量导入、状态切换、密码重置。

#### 仍存在静态演示或半成品特征的模块

- 教师端“竞赛模拟测试”“智能训练出题”大量使用前端静态数据。
- 学生端首页公告、近期赛事、猜你喜欢等内容大量硬编码。
- 学生端讨论区未接后端。
- 学生端智能组队、能力画像主要为静态展示。
- 学生端学习资源在接口失败时回退为示例数据。
- 管理员端 `sys-admin/dashboard`、`sys-admin/index`、`sys-admin/competition-screening` 仍是展示壳或模拟数据页。
- 学生端 AI 模拟答辩、材料优化已可调用外部能力，但配置方式、稳定性、安全性和平台内闭环不足。

---

## 3. 总体改造原则

### 3.1 优先原则

1. 优先补齐真实业务闭环，而不是继续叠加展示型页面。
2. 优先打通跨角色链路，例如学生提交材料后，教师评审、管理员统计都能看到同一份有效数据。
3. 优先替换静态数据页，因为这类页面最容易误导用户预期。
4. 优先补充关键统计、筛选、通知、状态反馈，提升运营效率。

### 3.2 建议分期

- P0：把静态演示页替换为真实业务页，修补关键断点。
- P1：增强三端协作与过程管理能力。
- P2：做智能化、分析化和运营提效能力。

---

## 4. 教师端需求

## 4.1 现状判断

教师端目前最成熟的是“评审管理”和“我的队伍赛事”链路，已具备：

- 查看可评审竞赛
- 查看参赛队伍详情
- 查看已评记录
- 提交/修改/删除评分
- 查看自己指导队伍的赛事情况

但教师首页中“竞赛模拟测试”“智能训练出题”等模块仍以静态数据为主，属于高可见但低真实度区域。

---

## 4.2 教师端需求清单

### T-01 教师首页静态模块改为真实业务数据

- 问题描述：
  - `src/views/teacher/index.vue` 中 `mockPublishedEvents`、`mockParticipationTrendData`、`mockScoreBandsBase` 等为前端硬编码。
  - 页面还存在“当前页面暂未接入后端”的提示，说明用户可见功能与实际能力不一致。
- 目标与价值：
  - 让教师首页成为真实的教学/评审工作台，而不是演示页。
- 优先级：P0
- 涉及模块：
  - 前端：`compserve-ui/src/views/teacher/index.vue`
  - 后端：新增教师端统计与训练发布相关接口
- 验收标准：
  - 教师端首页所有统计卡片、趋势图、列表数据均来自后端。
  - 页面不再出现“静态演示功能”提示。
  - 至少覆盖真实赛事统计、评审进度、指导队伍状态、训练发布记录四类数据。
- 实施建议：
  - 先保留现有 UI，替换数据源。
  - 分接口拆分：工作台概览、训练列表、成绩分析、待处理事项。

### T-02 教师评审页补充评审进度与异常提示

- 问题描述：
  - 教师已能评分，但对“我还差多少队伍未评”“哪些队伍材料缺失/不可预览”缺少统一视图。
- 目标与价值：
  - 降低教师评审遗漏率，提升评审完成效率。
- 优先级：P1
- 涉及模块：
  - 前端：`src/views/teacher/review/CompetitionDetail.vue`、`CompetitionReview.vue`
  - 后端：`TeacherController`、`ITeacherService`
- 验收标准：
  - 进入某赛事评审时可看到总队伍数、已评数、未评数、材料异常数。
  - 支持按“未评优先”“材料缺失”“已评过”筛选队伍。
  - 文件不可预览时展示明确原因和下载入口。
- 实施建议：
  - 在现有 `getReviewStats` 基础上扩展字段。
  - 把异常材料检测前置到列表层，而不是进入详情才发现。

### T-03 教师评分标准模板化

- 问题描述：
  - 当前评分更像单分值+评语，难以支持多维评分、统一尺度和复评场景。
- 目标与价值：
  - 提升评分一致性和可解释性。
- 优先级：P1
- 涉及模块：
  - 后端：评分实体、赛事配置、管理员赛事管理
  - 前端：教师评审页、管理员赛事配置页
- 验收标准：
  - 管理员可为赛事配置评分维度，如创新性、技术难度、展示效果。
  - 教师按维度评分，系统自动汇总总分。
  - 导出结果可显示维度得分明细。
- 实施建议：
  - 采用“赛事评分模板 + 队伍评分明细表”建模。
  - 兼容旧赛事，仅新赛事或开启模板配置的赛事启用。

### T-04 指导老师视角增加队伍过程管理

- 问题描述：
  - 当前“我的队伍赛事”更偏结果查看，缺少过程追踪。
- 目标与价值：
  - 帮助指导教师跟进报名、材料提交、评审状态、得分反馈。
- 优先级：P1
- 涉及模块：
  - 前端：`src/views/teacher/index.vue`
  - 后端：教师指导队伍查询接口
- 验收标准：
  - 教师可查看每支队伍的报名状态、材料提交状态、评分状态、最终名次。
  - 支持按“未提交材料”“待完善资料”“已出结果”筛选。
  - 支持导出我指导队伍的清单。
- 实施建议：
  - 与学生端报名/材料状态字段打通，避免教师端重复计算。

### T-05 教师端训练发布能力产品化

- 问题描述：
  - 当前“竞赛模拟测试”“智能训练出题”多为演示数据，没有形成可运营功能。
- 目标与价值：
  - 让教师真正可以基于竞赛主题发布训练，提高平台使用频率。
- 优先级：P2
- 涉及模块：
  - 前端：教师首页训练相关区域
  - 后端：训练任务、题目分发、参与记录
- 验收标准：
  - 教师可创建训练任务，选择目标竞赛、时间、题目来源、参与对象。
  - 学生端能收到训练任务并查看完成情况。
  - 教师可查看参与率、提交率、均分、薄弱知识点。
- 实施建议：
  - 第一阶段只支持从现有模拟题库选题发布。
  - 第二阶段再增加 AI 辅助出题。

## 5. 学生端需求

## 5.1 现状判断

学生端已经具备较完整的竞赛参赛链路，是当前最接近真实可用的角色端。成熟模块包括：

- 竞赛浏览与筛选
- 竞赛详情
- 报名与组队
- 邀请、申请、审批队员
- 材料提交
- 模拟考试
- 刷题训练

但学生端同时也是“半成品功能”最多的一端，首页、讨论区、智能组队、能力画像、AI 助手等存在明显的产品不一致问题。

---

## 5.2 学生端需求清单

### S-01 学生首页改为真实内容驱动

- 问题描述：
  - `src/views/student/index.vue` 中公告、近期赛事、猜你喜欢等内容大量硬编码。
  - 首页展示与后台赛事、公告、学习资源数据未完全打通。
- 目标与价值：
  - 让首页成为真实的竞赛门户，提高转化率和信任感。
- 优先级：P0
- 涉及模块：
  - 前端：`src/views/student/index.vue`
  - 后端：公告、推荐赛事、近期赛事、个性化推荐接口
- 验收标准：
  - 首页轮播、公告、近期赛事、推荐赛事均来自后端。
  - 推荐逻辑至少支持“热门赛事”“报名中赛事”“与用户专业/历史报名相关赛事”。
  - 后台变更赛事后，首页可同步反映。
- 实施建议：
  - 第一阶段先做通用推荐，不强依赖画像算法。
  - 保留现有视觉样式，优先替换数据源。

### S-02 竞赛报名页补齐过程校验与状态追踪

- 问题描述：
  - 报名链路已可用，但对学生来说“当前卡在哪一步”“还缺什么材料/信息”仍不够直观。
- 目标与价值：
  - 降低报名失败率和咨询量。
- 优先级：P0
- 涉及模块：
  - 前端：`competition-register.vue`、`profile/index.vue`
  - 后端：学生报名状态、资料完整度、材料状态查询
- 验收标准：
  - 报名流程可视化展示“个人资料完成 -> 队伍信息完成 -> 指导老师完成 -> 材料完成 -> 提交成功”。
  - 每个未完成项可直接跳转到对应修改位置。
  - 报名记录页能查看历史状态与时间线。
- 实施建议：
  - 将当前零散提示统一为步骤式状态组件。

### S-03 学生讨论区接入真实后端

- 问题描述：
  - `src/views/student/discussion.vue` 当前仍是前端本地新增、点赞、浏览，`loadDiscussions` 未接后端。
- 目标与价值：
  - 建立赛事交流与答疑沉淀区，减少重复咨询。
- 优先级：P0
- 涉及模块：
  - 前端：`discussion.vue`
  - 后端：讨论主题、回复、点赞、浏览量、标签、关联竞赛
- 验收标准：
  - 支持按竞赛查看讨论列表。
  - 支持发帖、回帖、点赞、浏览、置顶、删除。
  - 支持按标签筛选，如报名咨询、组队招募、经验分享。
  - 用户刷新页面后数据保留，不再依赖前端临时状态。
- 实施建议：
  - 第一阶段只做主题和回复，不做复杂审核流。
  - 管理员端后续补一个内容管理入口。

### S-04 智能组队从演示页升级为真实业务模块

- 问题描述：
  - `src/views/student/team-matching/index.vue` 目前队伍、推荐成员、申请列表均为静态数据。
- 目标与价值：
  - 将组队从报名页面的单点动作升级为平台能力。
- 优先级：P1
- 涉及模块：
  - 前端：`team-matching/index.vue`
  - 后端：队伍大厅、组队意向、推荐规则、申请记录
- 验收标准：
  - 学生可发布组队需求。
  - 学生可浏览公开队伍和公开招募信息。
  - 支持申请加入、队长审批、自动同步到竞赛报名队伍数据。
  - 推荐结果至少基于专业、技能标签、目标竞赛、年级四类信息。
- 实施建议：
  - 第一阶段先做“真实组队大厅”。
  - 第二阶段再做“智能匹配排序”。

### S-05 能力画像改为数据驱动

- 问题描述：
  - `src/views/student/ability-profile/index.vue` 当前为静态画像，缺少真实来源。
- 目标与价值：
  - 将模拟考、刷题、参赛成绩沉淀为学生成长反馈。
- 优先级：P1
- 涉及模块：
  - 前端：`ability-profile/index.vue`
  - 后端：画像统计、成长趋势、题目分类正确率、参赛记录聚合
- 验收标准：
  - 画像分数来源可解释，至少包含刷题、模拟考、竞赛参与三类数据。
  - 趋势图按月或按阶段展示能力变化。
  - 页面展示“建议提升方向”和推荐训练内容。
- 实施建议：
  - 第一阶段做规则型画像，不追求复杂 AI 模型。
  - 先解决“有真实数据”再优化可视化表现。

### S-06 刷题训练统计补齐真实趋势

- 问题描述：
  - `PracticeStudentController` 中概览统计部分已接题库和记录，但正确率趋势仍为示例数据。
- 目标与价值：
  - 让学生训练结果具备连续反馈。
- 优先级：P1
- 涉及模块：
  - 后端：`PracticeStudentController`、训练记录服务
  - 前端：`practice.vue`
- 验收标准：
  - 趋势图按日期展示近 7 天或近 30 天正确率变化。
  - 支持按题型、分类查看训练薄弱点。
  - 训练记录支持筛选和错题回看。
- 实施建议：
  - 基于 `practice_record` 聚合统计，不需要额外新表即可先落地。

### S-07 学习资源页去示例兜底，补完善链路

- 问题描述：
  - 学习资源页已接赛事数据，但接口失败时会回退到示例资源。
- 目标与价值：
  - 避免真实环境中用户看到不可信内容。
- 优先级：P1
- 涉及模块：
  - 前端：`learning-resources/index.vue`
  - 后端：学习资源聚合接口
- 验收标准：
  - 接口失败时展示空状态与重试，而不是示例数据。
  - 支持按赛事类型、主题、热度筛选。
  - 点击资源后能记录学习次数并统计热门资源。
- 实施建议：
  - 把示例资源保留在开发模式，不进入生产逻辑。

### S-08 AI 模拟答辩与材料优化纳入平台配置与审计

- 问题描述：
  - AI 功能已具备可用性，但依赖前端配置、外部地址、代理服务，稳定性和安全性不足。
- 目标与价值：
  - 把 AI 功能从“实验能力”变成“平台能力”。
- 优先级：P2
- 涉及模块：
  - 前端：`ai-assistant/mock-defense.vue`、`material-optimization.vue`
  - 后端：统一代理、文件上传、调用记录、失败重试、配额控制
- 验收标准：
  - 前端不暴露敏感 token。
  - 所有 AI 调用通过后端代理统一管理。
  - 支持调用日志、失败原因、历史记录、次数统计。
  - 支持管理员配置开关、额度和提示文案。
- 实施建议：
  - 优先把 token、上传、工作流调用迁移到后端。

---

## 6. 管理员端需求

## 6.1 现状判断

管理员端当前分成两类页面：

- 一类是已承接真实业务的页面，如竞赛管理、竞赛详情、题库管理、试卷管理、教师赋权、评分结果、教师/学生管理。
- 另一类是 `sys-admin` 下的管理驾驶舱、筛选台、部分看板页，视觉完成度高，但真实业务闭环不足。

当前最大问题不是“缺页面”，而是“部分页面看起来像成品，实际还是演示层”。

---

## 6.2 管理员端需求清单

### A-01 统一管理员入口，避免 `admin` 与 `sys-admin` 双轨割裂

- 问题描述：
  - 当前管理员能力分散在 `src/views/admin` 与 `src/views/sys-admin`，同一角色存在两套视觉和导航体系。
- 目标与价值：
  - 降低学习成本，减少重复维护。
- 优先级：P0
- 涉及模块：
  - 前端路由：`src/router/index.js`
  - 页面：`src/views/admin/*`、`src/views/sys-admin/*`
- 验收标准：
  - 管理员进入后只有一套主导航。
  - 竞赛管理、教师赋权、评分管理、用户管理等能力统一收口。
  - 原有功能入口不丢失，老链接可兼容跳转。
- 实施建议：
  - 优先保留已接真实接口的页面为主干。
  - `sys-admin` 静态页改为承接真实数据，或并入现有真实业务页。

### A-02 管理驾驶舱改为真实看板

- 问题描述：
  - `sys-admin/dashboard.vue` 当前统计数字、审核列表、评委列表均为本地静态数据和 `setTimeout` 模拟。
- 目标与价值：
  - 让管理员首页成为真实运营看板。
- 优先级：P0
- 涉及模块：
  - 前端：`sys-admin/dashboard.vue`

### C-01 统一状态字典与命名

- 问题描述：

- 问题描述：

- 优先级：P1
- 验收标准：
  - 文件预览组件统一。
  - 对不支持的格式展示明确提示和下载入口。
  - 记录预览失败原因，便于排查。

### C-03 统一运营通知能力

- 问题描述：
  - 学生首页公告、赛事通知、补充说明、报名提醒目前没有统一通知中心。
- 优先级：P1
- 验收标准：
  - 管理员可按赛事、角色、状态发送通知。
  - 学生端、教师端都有消息入口。
  - 支持已读/未读与重要通知置顶。

### C-04 统一数据埋点与行为统计

- 问题描述：
  - 当前很多页面已有“学习次数”“浏览数”等概念，但缺少统一统计口径。
- 优先级：P2
- 验收标准：
  - 至少记录赛事浏览、报名提交、材料上传、训练参与、评分提交、AI 功能调用等关键事件。
  - 管理员可查看基础转化漏斗。

## 12. 结论

当前项目不是“从零到一”问题，而是典型的“主链路已有、外围能力失真、静态页偏多”的阶段。

最值得优先投入的方向不是继续铺更多页面，而是：

1. 把教师端、学生端、管理员端已经曝光给用户的静态能力全部替换为真实业务能力。
2. 打通报名、材料、评审、成绩、通知这五条跨角色主链路。
3. 在主链路稳定后，再把智能组队、能力画像、AI 助手做成真正可运营、可审计、可统计的平台能力。
